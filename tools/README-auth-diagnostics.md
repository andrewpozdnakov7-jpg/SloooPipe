# Logcat диагностики авторизации

ZIP 10 расширяет диагностику после остановки встроенного входа на шаге Google 2FA.
Тег — `SloooPipeAuth`, сбор включён только в debug-сборках. WSL builder не менялся.
Это временный подробный режим для отладки; успешный вход он не подтверждает.

## Запись

Подключить телефон и начать запись до открытия приложения. PowerShell:

```powershell
adb logcat -v threadtime -T 1 SloooPipeAuth:V '*:S' | Out-File -FilePath .\slooopipe-auth.txt -Encoding utf8
```

Ubuntu/bash:

```bash
adb logcat -v threadtime -T 1 SloooPipeAuth:V '*:S' > slooopipe-auth.txt
```

Пройти вход, включая 2FA, дождаться результата или зависания ещё несколько секунд.
При успехе нажать «Передать сессию приложению» и выполнить проверку аккаунта/видео.
Остановить запись Ctrl+C. Не фильтровать по PID: окно входа работает в отдельном
процессе `:youtube_auth`. Фильтр по тегу включает оба процесса.

## Покрытие

- `process.*`, `login.*`: запуск, WebView engine/UA/settings, lifecycle, кнопки,
  геометрия/отступы, клавиатура, импорт, захват, очистка и возврат результата.
- `webview.navigation`, `page_started`, `page_finished`, `history`, `request`:
  host/path, имена параметров URL, разрешение перехода, метод, main-frame,
  заголовки запросов, длительность, наличие cookies/сессионных cookies.
- WebView HTTP/network/SSL ошибки: код, описание, заголовки ошибочного ответа;
  JS console: уровень, строка, сообщение и источник; завершение renderer.
- `webview.page_snapshot`: заголовок, readyState, видимый текст, действия/методы
  форм, типы/имена/required/disabled полей и подписи/disabled кнопок.
  Снимок делается после загрузки/изменения истории и каждые две секунды,
  пока Activity активна; одинаковые очищенные снимки повторно не печатаются.
  Значения полей ввода и HTML не считываются. На паузе polling останавливается.
- `storage.*`, `session.*`, `runtime.*`: Keystore/read/write, восстановление,
  CAPTURED/VERIFIED/generation, сброс кэша и плеера, logout и отмена старых операций.
- `http.*`, `backend.*`: DNS/connect/TLS, proxy type, времена/байты,
  запрос/ответ player API с очищенными заголовками, HTTP status/protocol,
  очищенные request/player/playability payload, причины отказа и числа форматов.
  WebView не предоставляет этим callbacks тела всех сетевых ответов или POST;
  успешные WebView response headers также не перехватываются.
- `account.*`, `extract.*`, `player.*`: проверка аккаунта, cache/network pipeline,
  отмена, playback state/isPlaying, первый кадр, track groups, размеры и ошибки.

## Формат и фильтрация

`seq`, `mono_ms`, thread, `op`, `screen`, `generation` связывают события. Seq/op
локальны процессу: PID и время logcat различают процессы. Длинная запись делится
на части по 900 Java chars с одинаковым seq и `part=n/total`, чтобы русский текст
не обрезался лимитом logcat. Текстовое поле ограничено 12000 символами.

Обычные строки и произвольные объекты по-прежнему не сериализуются. Для текста,
URL и Map/Iterable payload добавлены явные очищающие фабрики. URL сохраняет
host/path и имена query-параметров; userinfo, значения query и fragment удаляются.
Cookie/Authorization, секретные поля payload, email, коды/пароли, длинные непрозрачные
идентификаторы маскируются. Заголовки и payload ограничены по глубине/объёму.
Это эвристическая фильтрация диагностического текста, не гарантия удаления
любой возможной персональной информации из произвольного сообщения сервера.

Ошибки содержат AUTH code, очищенные сообщения, до 10 причин по 50 stack frames,
классы/сообщения suppressed exceptions; циклы причин ограничены. Старый uncaught
handler сохраняется, logger не подавляет исходный crash. Другие теги библиотек
не входят в указанный фильтр. Хранилище сессии и сырые credentials не выгружаются.

## Проверка

Здесь выполняются только статические проверки исходников. Gradle/компиляция,
JUnit и проверка нового APK на телефоне выполняются на другом компьютере.
Сборка и наличие логов не равны подтверждённой авторизации или воспроизведению.

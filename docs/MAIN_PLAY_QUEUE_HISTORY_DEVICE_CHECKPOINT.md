  кнопка отсутствует. YouTube Big Buck Bunny 60fps 4K (aqz-KE-bpKQ) играет
  1280x720/720p60; есть декодированный кадр и выбранный AAC-аудиопоток.
- Звук подтверждён через engine.audio_advancing и активный AudioFlinger track88
  PID14814, PCM stereo/44100 Hz. Человек звук не прослушивал.
- Пауза удерживает позицию 23548 ms; перемотка UI на 332573 ms остаётся на паузе;
  Play переводит в PLAYING, позиция достигает 338268 ms.
- Back ставит на паузу (340081 ms), мини-панель показывает правильные title/uploader
  и кнопку Play. Активен NewPlayerService; legacy PlayerService не играет.
  В dumpsys может оставаться DEAD connection старого сервиса — это не активный сервис.
- После аварии и нового запуска история содержит новый ролик (1 просмотр).
  Обычный Play из его карточки вызывает history.resume position=340081,
  сессия продолжает с 343064 ms; второй просмотр появляется в истории.
- «Добавить следующим» из контекстного меню истории добавляет другой ролик
  Big Buck Bunny в ту же очередь: MediaSession queue size=2, queue.append count=1 next=true.
- Play мини-панели возобновляет текущую очередь с 357220 ms.
  Android MEDIA_NEXT (keyevent87) переключает на добавленный ролик:
  active item id=1, title Big Buck Bunny, PLAYING с 21924 ms.
  После Back мини-панель показывает новый title, PAUSED с 28239 ms.

## Найденный блокер

Шаги: открыть ролик → Back → свернуть карточку → кнопка «Очередь воспроизведения».
Результат: приложение вылетает, PID14814 завершён.
Причина из stacktrace: NewPlayerException в getPlaylistDurationInMS(utils.kt:314),
вызванном из StreamSelectTopBar. QueueMediaRepository не передавал durationMs,
а прототип NewPlayer считал отсутствие длительности ошибкой.
Статически найден второй аналогичный throw в updateProgressInPlaylistOnce;
он также исправлен. Отдельный второй вылет на устройстве не воспроизводился.
Открытие/редактирование native UI очереди этим заблокировано. Полная приёмка этапа не пройдена.

## Исправление в ZIP23

- QueueMediaRepository и NetworkMediaRepository передают известную длительность
  конечных видео/аудио из секунд в миллисекунды.
- NetworkMetadata оставляет live/неизвестные значения null и защищает от переполнения.
- getPlaylistDurationInMS возвращает null при неизвестной/некорректной длительности
  или переполнении суммы, без исключения.
- Верхняя панель и строки очереди показывают --:-- при неизвестной длительности.
  Расчёт суммарной позиции также выдерживает неизвестные предыдущие элементы.
- Добавлены 5 JVM regression-кейсов NetworkMetadataTest (не запускались здесь).
- Builder, wrappers, версии инструментов, ключи и отдельное demo NewPlayer прежние.

# Окна авторизации на Android 16

Дата: 2026-10-20. Устройство пользователя: OnePlus 13, Android 16.
Предыдущий ZIP 06 успешно собран во внешнем WSL, включая app/shared/auth API tests.
Устройство выявило проблемы, которых статический анализ предыдущей версии не показал.

## Изменения ZIP 07

- По прямому указанию пользователя удалён единственный найденный `FLAG_SECURE`
  из PipePipeLoginActivity. Поиск по исходникам NewPipe и NewPlayer не нашёл
  других вызовов запрета скриншотов/записи экрана. Историческое ТЗ сохранено,
  но его требование для этого окна отменено последующей инструкцией пользователя.
- В окнах входа и аккаунта учитываются system bars, display cutout и IME insets.
  Кнопки имеют ширину контейнера и переносят текст. Управление входом помещено
  в ScrollView с ограничением половиной доступной высоты, остальное отдано WebView.
  Экран аккаунта прокручивается целиком. Для обоих окон включён adjustResize.
- Ручной импорт больше не вызывает WebView capture: ранее даже импортированные
  cookies требовали текущую страницу YouTube и её JS-конфигурацию, поэтому ошибка
  страницы Google ломала оба действия. Новая форма отдельно принимает Cookie header,
  MWEB clientVersion и необязательный VISITOR_DATA; она доступна и без WebView.
- Неверные поля показывают конкретные сообщения, диалог остаётся открыт.
  При закрытии поля очищаются; секреты в сообщения не включаются. Строка `Cookie:`
  при вставке заголовка удаляется, проверки SAPISID и запрета CR/LF сохраняются.
- Захват встроенной сессии отдельно сообщает об отсутствии cookies или версии
  клиента; для конфигурации MWEB предлагает перейти на m.youtube.com.
  Ответ JS после ухода со страницы/закрытия Activity не принимается.
- Добавлена кнопка обычного браузера. Browser selector исключает перехват ссылки
  обработчиком YouTube внутри приложения. Вход во внешнем браузере не считается
  передачей сессии: возвращать cookies автоматически этот механизм не умеет.

## Отказ Google принимать браузер

Google может запрещать вход из встроенного браузера;
см. [справку Google](https://support.google.com/accounts/answer/7675428?hl=en).
Пока неизвестно, видел ли пользователь отказ именно во встроенном WebView или
в отдельном браузере: уточнены модель/Android, но не место появления сообщения.
ZIP 07 не заявляет обход этого отказа, не заменяет SAPISID-сессию OAuth-токеном
и не маскирует один успешный вход в браузере под VERIFIED в приложении.
Для переноса сессии внешнего браузера нужен явный ручной импорт её данных.

Insets добавлены по [документации Android](https://developer.android.com/develop/ui/views/layout/edge-to-edge).
Визуальная причина на устройстве пока не подтверждена скриншотом: до исправления
его блокировал FLAG_SECURE. Отступы/прокрутку нужно проверить на телефоне.

## Проверка на устройстве

1. Собрать withAuth ZIP 07, установить подписанный APK из нового run-каталога.
2. Сделать скриншот экрана аккаунта и окна входа. Проверить обычный/разделённый
   экран, обе ориентации, увеличенный шрифт, видимость кнопок при клавиатуре.
3. Проверить, что controls прокручиваются, WebView сохраняет место на экране.
4. Открыть импорт на странице Google и без завершённого WebView-входа:
   отсутствие cookies/версии показывает ошибку нужного поля и не закрывает форму.
   Отмена возвращает к входу; не должен возникать ложный успешный вход.
5. Проверить внешнюю кнопку: открывается настоящий браузер. Если Google снова
   отказывает, сохранить скриншот с сообщением и название браузера.
6. При наличии собственных cookies и MWEB version импортировать их явно,
   затем проверить получение и отдельно воспроизведение видео. Без таких данных
   ручной импорт сам по себе не решает серверный отказ Google.

Локально: Java parse/Checkstyle двух изменённых Activity, XML, ссылки на строки,
поиск capture restrictions и проверка ZIP. Gradle, компиляция, проектные тесты
и работа интерфейса/входа на устройстве здесь не запускались. SABR/NewPlayer
в этот пакет не входят.

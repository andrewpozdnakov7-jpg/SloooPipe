# Локальный просмотр через NewPlayer — первый этап

В списке источников после всех сервисов добавлен пункт **«Локальное»**.
Он открывает `NewPlayerActivity` внутри основного APK SloooPipe. Сетевой сервис
Extractor не подменяется фиктивным ID, выбранный ранее источник сохраняется.

Системный выбор документа (`OpenDocument`, `video/*`) передаёт `content://` URI
в `LocalMediaRepository`. Чтение и получение метаданных выполняются вне UI-потока.
Доступ используется через выданное Android разрешение; путь к файлу не угадывается,
общее разрешение на все видео для этого сценария не запрашивается. При доступности
сохраняется persistable grant для восстановления после пересоздания процесса.

Основной APK напрямую зависит от `:newplayer-local` — исходников NewPlayer/dev
`212ca1c8d9419a19cb5aed7f0a61e22e8732a25c`, Media3 1.9.2. Официальный API Codeberg
подтвердил этот SHA 2026-10-21. Полный источник и локальные изменения описаны в
`NewPipe/third-party/NewPlayer/SLOOOPIPE.md`. Старый отдельный демонстрационный
проект `NewPlayer/` сохранён и не используется основным APK.

Репозиторий возвращает MediaItem, а фабрика ExoPlayer использует DefaultDataSource
для URI из системного выбора. Экран отображает настоящие NewPlayerView и
NewPlayerViewModelImpl. Application и MediaSessionService получают один экземпляр
NewPlayer. Авторизация, YouTube и получение сетевых потоков здесь не вызываются.
Старый плеер NewPipe останавливается перед запуском выбранного файла.

Связаны встроенные органы управления NewPlayer, полноэкранный режим, изменения
ориентации, callback PiP, выход в SloooPipe и сохранение позиции в instance state.
При уходе с экрана просмотр ставится на паузу, кроме активного PiP. При завершении
Activity плеер освобождается. Полноценный фоновый аудиорежим не является целью
этого этапа. Возможности PiP и восстановления нужно подтвердить на устройстве.

Диагностика: `SloooPipeLocal` — создание экрана и движка, выбор/отмена файла,
доступность документа, MIME/размер, состояния и ошибки Media3, выбранные дорожки,
кодеки, размер кадра, первый показанный кадр, PiP и освобождение экрана. Секреты
YouTube не передаются в этот путь. Полный URI и имя файла не добавляются в наши
события диагностики; сторонние исключения сохраняются со стеком для разбора.

## Сборка и проверка на телефоне

Использовать прежний скрипт и компонент `main`; отдельный APK NewPlayer не нужен.
Режим `--auth with` или `--auth without` не должен влиять на локальный просмотр.
Существующая сборка YouTube и старый плеер для сетевых видео сохраняются.

1. Открыть выбор источника, убедиться, что «Локальное» находится последним.
2. Выбрать файл, реально лежащий на телефоне, например обычный MP4 с H.264/AAC.
3. Проверить изображение, звук, паузу, продолжение и перемотку.
4. Включить полноэкранный режим, повернуть телефон, выйти из полноэкранного режима.
5. Выбрать второй файл, отменить повторный выбор, вернуться в SloooPipe и открыть
   «Локальное» заново. Проверить понятное сообщение для недоступного/битого файла.
6. Повторить локальный просмотр без сети; отдельно проверить PiP и восстановление
   позиции после пересоздания Activity/процесса.

Успех этого этапа — файл играет через NewPlayer в основном APK. Это не подтверждает
воспроизведение YouTube, выбор сетевого качества или полную замену старого плеера.
ZIP17 собран пользователем на основном компьютере; предоставленный APK
проверен через ADB в LDPlayer14 / Android14. Подтверждены изображение H.264,
выбор AAC-дорожки, пауза, seek, fullscreen, Back/Home и повторное открытие.
Звук на слух и OnePlus13/Android16 не проверены. Местная компиляция не запускалась.

В этапе2 общий host/runtime перенесены в пакет `newplayer`; локальный
`LocalMediaRepository` сохранён. Пустой экран больше не показывает загрузку
до выбора файла. Регрессионная проверка нового APK ещё требуется.
Следующий шаг описан в [NETWORK_NEWPLAYER_STAGE2.md](NETWORK_NEWPLAYER_STAGE2.md).

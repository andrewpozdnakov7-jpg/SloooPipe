# APK34: кнопка скорости и ошибка восстановления паузы; ZIP35

Дата: 2026-10-23. LDPlayer14 / Android 14 / API 34, экран 720×1280.
APK SHA256 `67367d66d0f47080277ad30076e83250d8242ecc8ffc5a65e18126c7ec0c5b8b`,
45,426,082 байта; пакет `org.schabi.newpipe.debug`, PID 18400. По сравнению с извлечённым
APK33 изменён classes2.dex. Пользователь установил сборку из ZIP34; полная аттестация
сборки и WSL test XML не предоставлены. Здесь не запускались Gradle, компиляция или
проектные JVM-тесты. Слышимый звук пользователь проверит отдельно на телефоне.

## Подтверждено на APK34

- **Исправление кнопки ZIP34 работает.** В портретном режиме значения 1x, 1,25x,
  1,5x и 2x отображаются в одну строку. Высота текста при обычном шрифте — 40 px;
  значение 1,25x имеет ширину 71 px. В APK33 суффикс x переносился вниз.
- Значения совпадают с `engine.timeline speed=1.25/1.5/2.0`. На паузе изменение
  скорости сохраняет выбранный элемент; позиции 227083→227089 мс, затем 227089 мс.
  Доказательства: 02–06, speed-cases.json.
- Полноэкранный landscape 1280×720 и возврат к встроенному portrait сохраняют
  1,25x и PAUSED 227089 мс. Подпись остаётся в одну строку: 07–08.
- При font_scale 1.3 подпись 1,25x также помещается в одну строку (94×54 px): 09.
  Но этот переход выявил отдельную ошибку сохранения паузы, описанную ниже.
- После возврата обычного шрифта подпись и кнопка доступны: 15–16. Скорость возвращена
  в 1x. Сетевой ролик играет; пауза и перемотка работают: 17–18.

Проверка font_scale 2.0 не завершена: вспомогательный поиск контролов не нашёл подпись.
Его жест в центре экрана мог попадать по другим элементам после изменения геометрии.
Это не доказательство дефекта приложения при 2.0; результат NOT VERIFIED.
Проверку переноса при всех возможных настройках шрифта не заявляем.

## FAIL: Activity recreation снимает паузу

Воспроизводится после обычного Play, когда Intent содержит `EXTRA_RESUME_ACTIVE`:

1. Поставить сетевой ролик на паузу в NewPlayer.
2. Изменить системный размер шрифта, чтобы Android пересоздал Activity.
3. Не нажимать на элементы интерфейса.

Контрольный повтор 12→13 исключает нажатия между измерениями. До изменения:
PAUSED 271677 мс, текущий элемент 0. После `font_scale=1.3`: PLAYING 271691 мс,
тот же элемент и PID. В логе: `screen.destroy finishing=false`, затем
`screen.create network=true restored=true`, затем `engine.playing=true`.
После остановки позиция 274596 мс подтверждает, что воспроизведение действительно шло.
Возврат обычного шрифта тоже пересоздал Activity и повторил Play. Затем пауза
восстановлена вручную. Это дефект приложения, а не промах автоматизации.

Причина в `NewPlayerActivity.onCreate`: команда `EXTRA_RESUME_ACTIVE` повторно
читалась из прежнего Intent и вызывала `runtime.player.play()` даже при ненулевом
`savedInstanceState`. Сохранённый живой движок до этого оставался на паузе.

## Исходная правка ZIP35

Единственный production-файл — `NewPlayerActivity.kt`. Выполнение стартового Resume
в `onCreate` ограничено `savedInstanceState == null`. Пересоздание экрана сохраняет
текущее намерение Play/Pause живого движка. Явные запросы через `onNewIntent` остаются
без изменений; сохранённое состояние не навязывается поверх более нового состояния движка.

Ktlint изменённого файла: 0 ошибок до и после. `git diff --check` PASS. Новые проектные
JVM-тесты не выполнялись. ZIP35 **ещё не собран и не проверен на устройстве**. Нужны
повторы fresh Play → Pause → font1.3 → default без самопроигрывания; Playing → recreation;
обычный Play и повторное открытие через мини-панель. Обе auth сборки/test/isolation и
полные XML/counts остаются внешней проверкой.

Кнопка скорости, generic NewPlayer patch, зависимости, signing и builder09 не менялись
относительно ZIP34. Старые source/report ZIP неизменны. Upstream build/demo/PR не выполнялись.

## Границы проверки

[Матрица APK34](APK34_ACCEPTANCE.csv) описывает этот узкий прогон. 10+10 циклов очереди,
local mp4, popup/PiP и stale consent из [APK33](APK33_DEVICE_CHECKPOINT.md) остаются
историческими результатами и не переносятся на APK34/35 автоматически.
Чёрный первый кадр нового ролика при паузе в позиции 0 остаётся известным ограничением.
Полная source/track/history/resume/lifecycle матрица, network/media failure recovery,
физические Android16/audio-focus/headset/noisy проверки не закрыты.

Размер шрифта возвращён к эффективному значению 1.0 (Android записал 1.0 вместо
исходного отсутствующего ключа); ориентация и скорость возвращаются к portrait/1x.
Данные/история не очищались. Raw APK, общие logcat, ключи и аккаунтные сессии не публикуются.

Мини-панель и открытие/закрытие очереди проверены отдельно: 20–23. Без выбора другого
ролика сохраняется элемент 0 и PAUSED296644→296656 мс (12 мс). В конце — Main с сетевой
мини-панелью, PAUSED296656, speed1x, portrait, эффективный font_scale1.0. PID18400 и SHA256
установленного APK не изменились; в сохранённом конечном логе этого PID0 FATAL EXCEPTION.
Падений не наблюдалось, но самопроигрывание при recreation остаётся FAIL APK34.

# Порядок зависимостей и оформление auth-кода

Дата: 2026-10-20. Лог: `03 delivery/auth-stage1-20261020-02/build-main.log`.
Исходный ZIP 04: `a4b60af333c8e9aaf4445fb27438a9c0d5af987c562c1819bd7684bde809f9a1`.

Во внешней WSL-сборке скомпилировались auth API и локальный Extractor.
Сборка остановилась на `:app:checkDependenciesOrder`: alias `android-auth-library`
находился перед `about-libraries` вместо позиции после `android-application`.
Перемещена только запись; версия и plugin ID не менялись.

Весь TOML проверен на синтаксис и порядок строк по алгоритму из
`buildSrc/src/main/kotlin/CheckDependenciesOrder.kt` (сброс порядка на заголовках,
пропуск пустых строк и комментариев).

В `preDebugBuild` также обязательны проверки Java. Поэтому отдельно от Gradle
запущен статический Checkstyle 13.4.2 с конфигурацией проекта на всех семи
добавленных/изменённых Java-файлах host app после коммита `7a8d9f3`.
Обнаружены и исправлены 141 нарушения: оформление блоков, длина строк,
final у неизменяемых локальных переменных/параметров, закрытые конструкторы
двух служебных AuthBinding. Для изменяемого параметра обхода exception causes
введена локальная переменная `current`, предел обхода прежний — десять причин.
Настройки Checkstyle и список проверяемых source sets не ослаблялись.

После исправления Checkstyle сообщает ноль нарушений на этих семи файлах;
все семь проходят синтаксический Java parser. Отчёты сохранены в delivery 03.
JAR Checkstyle скачан из официального GitHub release `checkstyle-13.4.2`;
google-java-format 1.24.0 использован только как форматтер пяти новых host файлов.

Это статический анализ, не сборка: Gradle, компиляторы, проектные тесты и
проверка воспроизведения на этом компьютере не запускались. Нужен повтор
обоих WSL-вариантов с ZIP 05. SABR и NewPlayer остаются незавершёнными.

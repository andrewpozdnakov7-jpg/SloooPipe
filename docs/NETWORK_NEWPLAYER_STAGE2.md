# Сетевой ролик NewPipe через NewPlayer — этап 2

> Историческое описание ZIP18–20. В ZIP21 обычный Play, очередь и история подключены
> в исходниках: [этап 3](MAIN_PLAY_QUEUE_HISTORY_STAGE3.md). Его APK ещё не проверен.

Контрольная точка: выбранный в NewPipe обычный сетевой ролик воспроизводится
через NewPlayer с изображением, звуком, паузой и перемоткой. Мост проверен в установленной внешней сборке ZIP18 на LDPlayer/Android14:
обычный YouTube-ролик и HLS live воспроизводились через NewPlayer. Подробности и границы
проверки: [контрольная точка](NETWORK_NEWPLAYER_DEVICE_CHECKPOINT.md). ZIP20 содержит
последующие изменения навигации; их проверка в новом APK ещё предстоит.

## Как открыть

На экране информации выбранного ролика нажать **«Смотреть через NewPlayer»**.
Это отдельная кнопка перед стандартной панелью действий. Действие работает
после получения `StreamInfo`; во время загрузки информации запуск не выполняется.
Обычный запуск NewPipe пока использует прежний плеер. Автоматического перехода
с нового пути на старый при ошибке нет. Локальное видео открывается прежним
пунктом «Локальное» в конце выбора сервисов.

## Реализация

`VideoDetailFragment` -> `NewPlayerActivity.openNetwork(StreamInfo)` ->
небольшой ограниченный in-memory handoff -> `NetworkMediaRepository` ->
`NetworkStreamSelector` -> `MediaItem` с планом источников в `tag` ->
`NewPlayerImpl` -> `NetworkMediaSourceFactory` -> Media3 1.9.2.

Интеграция находится в `app/.../org/schabi/newpipe/newplayer/`:

- `NewPlayerActivity` и `NewPlayerRuntime` — общий host для локальных и сетевых
  видео. Прежние LocalVideoActivity/LocalPlayerRuntime перенесены в этот пакет;
  локальный LocalMediaRepository остаётся отдельным адаптером. NewPlayerProvider
  приложения и MediaSessionService получают один общий экземпляр NewPlayer.
- Используется upstream MultiRepository с ключами `local:` и `network:`.
- `NetworkMediaRepository` принимает уже извлечённый `StreamInfo`, читает
  предпочтения NewPipe по разрешению/аудиодорожке. В Intent передаются ID сервиса,
  ссылка страницы, позиция и непрозрачный ключ, а не сериализованный StreamInfo
  или большие подписанные URL. После потери памяти предусмотрено повторное
  извлечение; полная проверка восстановления процесса остаётся впереди.
- Поддержан обычный HTTP progressive: готовое видео со звуком или отдельные
  видео/аудио с `MergingMediaSource`. Если аудио для video-only отсутствует,
  выбирается доступное muxed-видео либо manifest; немое video-only не считается
  успешным вариантом. Фильтрация выполняется до preference grouping/deduplication.
- Manifest URL HLS/DASH обрабатываются Media3. У live приоритет HLS, затем DASH;
  наличие и величина seekable DVR window зависят от источника. Для контрольной
  точки перемотки сначала использовать конечный обычный ролик, не live.
- Для YouTube progressive adaptive сохраняется генерация segment-base DASH
  через существующий Extractor creator; при невозможности генерации остаётся
  progressive source той же выбранной дорожки, без замены движка.
- `datasource/YoutubeHttpDataSource.java` — механический перенос существующего
  NewPipe `player/datasource/YoutubeHttpDataSource.java` на пространства имён
  Media3 с сохранением комментариев/происхождения. Это не заново придуманный
  протокол: сохранены POST, Range/rn и visionOS/web headers. Маршрутизация
  использует его только для YouTube `/videoplayback` на googlevideo.com и его
  поддоменах; manifest и остальные адреса используют обычный GET data source.
- HLS/DASH зависимости 1.9.2 объявлены в основном app явно. Библиотека
  NewPlayer и её ревизия не обновлялись; инструменты сборки и builder прежние.
- Перед открытием Activity старый PlayerHolder останавливается ещё в вызывающем экране,
а VideoDetailFragment отключает autoplay и восстановление прежней очереди по Back.
Явный выбор старого плеера или другого ролика снимает этот запрет. Дополнительная
остановка PlayerHolder остаётся при открытии нового источника. При Home
  загрузка отменяется, плеер ставится на паузу, ещё не запущенные playback jobs
  инвалидируются. При завершении Activity движок освобождается. Нужен APK-тест
  жизненного цикла: это не утверждение о проверке всех гонок.
- Смена auth generation сбрасывает сетевой handoff и останавливает текущий
  новый сетевой плеер. Готовые результаты старой generation не запускаются.
  Локальное видео не требует авторизации и не останавливается этим guard.
- «Повторить» выполняет force reload через существующий ExtractorHelper.
- Индикатор загрузки на пустом локальном экране скрыт до выбора файла.

## Диагностика

Тег `SloooPipeLocal` сохранён для совместимости существующих фильтров и теперь
описывает оба режима. Основные события: `network.plan`, `network.handoff_ready`,
`network.source_create`, `network.open`, `network.load_complete/load_error`,
`engine.first_frame`, `engine.audio_advancing`, `engine.track`, `engine.state`,
`engine.playing`, `engine.timeline`, `legacy.handoff`, `screen.failure`. В HTTP-событиях есть host, позиция/длина,
тип/объём загрузки и HTTP status; нет query подписанных URL, cookies или headers.
Стеки новых ошибок направляются через существующий очищающий AuthDiagnostics
в `SloooPipeAuth` для debug APK. `audio_advancing` — признак продвижения аудио
в Media3, а не проверка звука на слух на физическом устройстве.

## Проверки и критерий приёмки

Добавлены 9 JVM unit-тестов `NetworkStreamSelectorTest`: muxed, merge с выбранным
аудио, отсутствие аудио, fallback manifest, live priority, torrent/file rejection
и некорректный preferred index. Здесь они не запускались: их выполняет обычный
`main / build-test` на сборочном компьютере вместе с остальными app-тестами.

1. Собрать новый полный source ZIP обычным WSL builder, `--component main`.
   После ZIP20 дополнительно пройти сценарии возврата из контрольной точки.
2. Открыть обычный конечный сетевой ролик и дождаться информации о нём.
3. Нажать «Смотреть через NewPlayer», подтвердить новую Activity/MediaSession
   и события `network.*`, `engine.first_frame`, выбранную audio-дорожку.
4. Проверить изображение и услышать звук. При наличии звука на устройстве,
   `audio_advancing` и валидной аудиодорожки зафиксировать отдельные свидетельства.
5. Пауза: позиция не меняется. Продолжение: позиция растёт.
6. Seek в середину: меняется позиция и показывается соответствующий участок,
   продолжаются изображение и звук. Для раздельных потоков проверить синхронность.
7. Fullscreen/Back/Home, повторное открытие другого ролика, локальный MP4 как
   регрессия. Ошибка нового пути не должна запускать старый плеер.

Контрольная точка считается достигнутой после проверки нового APK по пунктам
изображение/звук/пауза/seek. Результаты ZIP17 относились только к локальному
MP4 и не переносятся на этот этап автоматически.

## Ограничения

Нет полного переноса очереди/истории, фонового аудиорежима, network recovery,
субтитров/глав/превью, полной смены качества или всех delivery methods. Нет
поддержки SABR и полного PoToken pipeline. Inline manifest/OTF/post-live DVR
не добавлены общим адаптером; поддержаны перечисленные progressive и URL
manifest варианты. Сетевые ошибки Extractor/auth по-прежнему возможны.
DRM не является целью. PiP/process-death/Android16/долгие сеансы не проверены.
Жизнеспособность одной YouTube-трансляции в старом PlayerService не доказывает
работоспособность ни обычного видео, ни нового сетевого моста.

Исходники остаются в локальном Git. Этот этап не разрешает их публикацию.

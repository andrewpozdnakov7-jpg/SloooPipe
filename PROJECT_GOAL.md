# Цель SloooPipe

Привычные сценарии NewPipe должны работать через NewPlayer, а исходная команда и
другие разработчики — иметь возможность изучить и использовать реализацию.
Придумывать отличия от PipePipe/Straw для этого не требуется.

Согласованное задание22 октября включает три части: функциональная интеграция,
архитектура/Kotlin и подготовка переносимых изменений upstream. Все три входят в
текущую работу, затем следуют внешние build/test/device циклы до приёмки по матрице.

Рабочее дерево — `00 src`; `01 start` сохраняется как reference-only. Здесь
выполняются source edits, static lint/review, локальный Git, ZIP и ADB-проверки
установленного APK. Gradle, компиляцию APK и проектные тесты запускает пользователь
на основном компьютере в WSL. Новый APK проверяется заново.

APK31 подтвердил snapshot repeat/shuffle и очистку mini после last deletion/Back.
Автоматическое закрытие пустого host остаётся FAIL; ZIP32 переносит наблюдение на
release движка. Нужны внешняя сборка и новый device-цикл. [Checkpoint](docs/APK31_DEVICE_CHECKPOINT.md),
[матрица](docs/APK31_ACCEPTANCE.csv), [результат](RESULT.md).

Отключаемая авторизация остаётся экспериментальной. Гарантировать доступ к любому
YouTube-ролику и независимо реализовать весь SABR/PoToken — отдельная цель.
Результат upstream ещё не принят, PR/письма не отправлялись.

Ошибка компиляции ZIP30 и исправление одной строки API в ZIP31: [разбор](docs/ZIP30_BUILD_FIX.md).

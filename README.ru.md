# SloooPipe

Экспериментальная интеграция **NewPipe с NewPlayer**. Цель — привычные сценарии
NewPipe через NewPlayer и реализация, которую исходная команда и другие проекты
смогут изучить и использовать.

[English](README.md)

**Ранняя разработка.** В репозитории опубликованы исходники приложения, включая
исправление очереди ZIP23. Его APK ещё не проверен; последние результаты на
устройстве относятся к APK22. Стабильного выпуска пока нет.

## Что проверено

На APK22 в LDPlayer / Android 14:

- Обычный Play в карточке NewPipe открывает NewPlayer.
- YouTube-ролик воспроизводится с изображением 1280×720. Подтверждены кадр,
  AAC-поток и аудиовывод до микшера Android. Человек звук не прослушивал.
- Работают pause/seek/play. Back сохраняет очередь на паузе и мини-панель с
  правильным названием; Play мини-панели продолжает воспроизведение.
- Просмотр появляется в истории NewPipe. После перезапуска приложения ролик
  продолжается с сохранённой позиции.
- «Добавить следующим» добавляет второй ролик. Системная команда MEDIA_NEXT
  переключает на него, мини-панель показывает новое название.

На прежнем APK20 проверялись выбранные сценарии локальных файлов и трансляций.
Они ещё не все повторены на текущем снимке.
[Подробные результаты и оставшаяся приёмка](docs/MAIN_PLAY_QUEUE_HISTORY_DEVICE_CHECKPOINT.md).

## Известные проблемы и ограничения

- **APK22 вылетает при открытии UI очереди:** NewPlayer требует длительность
  в метаданных. ZIP23 передаёт известные значения и поддерживает неизвестную/live
  длительность в UI и суммарной позиции. Исправление проверено статически;
  повторная проверка нового APK предстоит.
- Редактирование очереди, repeat/shuffle, автоматический next, длинные плейлисты
  с пагинацией и полный жизненный цикл очереди ещё требуют приёмки на устройстве.
- Авторизация YouTube и авторизованное воспроизведение экспериментальные.
  Захваченная сессия браузера не подтверждает доступность конкретного видео.
  Полные SABR и PoToken не реализованы.
- Фон и popup пока используют прежний плеер. Полный перенос PiP/фона и
  восстановление всей очереди после смерти процесса не завершены.
- Проверки на физическом Android 16 и полная матрица источников/жизненного цикла предстоят.
- В debug-сборках оставлена подробная диагностика. Диагностика авторизации очищает
  чувствительные значения и выключена в release. Проверяйте логи перед публикацией.

## Сборка и тесты

В основном приложении зафиксированы JDK 21, Gradle 9.8.2, AGP 9.4.1, Kotlin 2.4.21,
SDK platform 37.0 и Build Tools 36.0.0. Первый запуск требует доступа к репозиториям
зависимостей или заранее подготовленного кэша.

В Linux/WSL:

```bash
git clone https://github.com/andrewpozdnakov7-jpg/SloooPipe.git
cd SloooPipe/NewPipe
chmod +x gradlew
./gradlew :app:testDebugUnitTest :youtube-auth-api:test :shared:jvmTest \
  :app:verifyAuthIsolation :app:assembleDebug -Pslooopipe.withAuth=false
```

Задайте `JAVA_HOME` и `ANDROID_HOME`. Для `:shared:jvmTest` нужен дисплей; на машине
без дисплея запускайте Gradle-команду через `xvfb-run -a` с установленными Xvfb/xauth.
Для экспериментальной авторизации используйте `-Pslooopipe.withAuth=true`.
Это инструкция тестовой сборки, а не заявление об успешном выполнении всех задач
текущего снимка. 22 JVM-кейса app/NewPlayer, включая пять новых тестов длительности,
на этом компьютере не запускались.

Прежний процесс сборки ZIP описан в [`tools/README-wsl.md`](tools/README-wsl.md).
Для него нужны собственные ключи и локальные настройки подписи во внешнем
сборочном каталоге. Ключи проекта и сессии аккаунтов не распространяются.
Upstream build добавляет Git-ветку к debug applicationId; ZIP-builder создаёт
локальные метаданные `dev`, чтобы получить постоянный суффикс `.debug`.

## Участие

Начните с контрольной точки и архитектуры. Для ошибки указывайте точный коммит,
версию Android и режим авторизации. Удаляйте из логов cookies, токены, сведения
аккаунта и приватные URL перед публикацией.

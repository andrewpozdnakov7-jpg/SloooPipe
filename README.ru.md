# SloooPipe

Экспериментальная Android-интеграция **NewPipe с NewPlayer**. Цель — подключить
привычные сценарии NewPipe к NewPlayer и дать другим разработчикам реализацию,
которую можно изучить, адаптировать и использовать.

[English](README.md) · [Результаты](RESULT.md) · [Архитектура](docs/NEWPLAYER_SESSION_INTEGRATION.md)

`2c22439`. Оба auth-варианта прошли [GitHub Actions](https://github.com/andrewpozdnakov7-jpg/SloooPipe/actions/runs/40319678374): **264 теста на вариант**

Auth-enabled APK установлен и проверен в обновлённом LDPlayer / Android 14.
Исправлен запуск с `t=0`, когда экстрактор переписывает URL и в кэше есть история.
Обычная ссылка продолжает просмотр; отдельный путь без автовоспроизведения тоже
прошёл. Проверены шрифт 200%, возврат изображения из автоматического popup,
сохранение окна/поворот, возврат из очереди и локальное видео с мини-панелью.
Auth-free APK прошёл CI; на эмуляторе в этом прогоне он не проверялся.
После поворота popup на паузе возможна задержка кадра: в одном повторе чёрное
окно через 2 секунды показало изображение через 8. Это открытый PARTIAL;
успешная проверка геометрии не означает приёмку изображения при повороте.

Это покрытие, а не процент готовности. Результаты старого APK не переносятся
автоматически на новый. Ранее проверялись live HLS/DVR, субтитры, главы,
скорость/качество, настройки истории, большие очереди, фон/popup/PiP и восстановление
после сетевой ошибки. [Текущие результаты и ограничения](RESULT.md).

**Стабильного релиза нет.** Диагностика debug включена. YouTube в проверенном
окружении требует подтвердить «не бот»; авторизация не гарантирует воспроизведение.
Физический Android 16 и слышимый звук ждут проверки на телефоне. Декодированный
язык/pitch, remote DASH, scheduled/post-live и SoundCloud проверены частично либо
не проверены. Первый кадр нового сетевого ролика на паузе в нуле может быть чёрным;
локальный ноль отрисовался. Android Auto, полный SABR/PoToken и перенос всей ветки
refactor не приняты. Действия внешнего плеера/Kodi остаются внешними.

## Сборка и тесты

[GitHub Actions: сборка, тесты и подпись существующим ключом](docs/CI_BUILD.md).
Ручной workflow поддерживает оба auth-варианта и сохраняет APK/отчёты.
В этом репозитории настроена существующая подпись; оба варианта CI прошли.
Для собственного форка настройте свои signing secrets.


Нужны Linux/WSL, JDK 21, Android SDK platform 37.0 и Build Tools 36.0.0.
Для основного приложения зафиксированы Gradle 9.8.2, AGP 9.4.1, Kotlin 2.4.21 и
Media3 1.9.2. Gradle wrapper включён. Для headless JVM-тестов shared нужны Xvfb/xauth.
SDK и зависимости должны быть установлены или доступны по сети; полного офлайн-набора здесь нет.

```bash
git clone https://github.com/andrewpozdnakov7-jpg/SloooPipe.git
cd SloooPipe/NewPipe
# Для существующей копии или архива исходников перейдите в её каталог NewPipe.
chmod +x gradlew
# Задайте JAVA_HOME и ANDROID_HOME для Linux JDK и SDK.
xvfb-run -a ./gradlew :app:testDebugUnitTest :youtube-auth-api:test :shared:jvmTest :app:verifyAuthIsolation :app:assembleDebug -Pslooopipe.withAuth=true
```

Повторите с `-Pslooopipe.withAuth=false` для варианта без авторизации.
Оба варианта прошли текущий CI: 218 app-тестов, включая все 63 кейса интеграции
NewPlayer, плюс 15 auth API и 31 shared на вариант. Скачанные XML проверены.
Прежний WSL-прогон остаётся сообщением пользователя без полных отчётов.
Обычная сборка checkout сохраняет APK в `NewPipe/app/build/outputs/apk/` и использует
свою debug-подпись. APK с другим сертификатом не обновит существующую установку.

Для выбора ZIP, сохранения отчётов запуска и подписи существующим внешним ключом
есть [инструкция WSL-скрипта](tools/README-wsl.md), ревизия
`20261022-09-memory-cleanup`. Скрипту нужны внешние файлы `signing/`; зависимости
сохраняются, после работы он пытается освободить чистый файловый кэш Linux в RAM.
Очистку можно отключить через `--no-memory-cleanup`. Текущий preview содержит
исходники точного CI-коммита; ZIP36 и прежние архивы остаются историческими.
В публичной `main` документация может быть новее. Тег релиза указывает на
проверенные исходники; выше описано создание ZIP из копии репозитория.

## Участие и использование кода

Начните с [цели проекта](PROJECT_GOAL.md), [управления сессией](docs/NEWPLAYER_SESSION_INTEGRATION.md)
и [разбора переноса upstream](docs/UPSTREAM_PORTING_20261022.md). Общие изменения
NewPlayer отделены от NewPipe-хостов. Проверка текстового применения переносимых
патчей не заменяет сборку или принятие upstream. PR разработчикам пока не отправлялись.

В отчёте об ошибке укажите коммит, SHA256 APK, Android, вариант авторизации и шаги
воспроизведения. Разделяйте статический анализ, сборку/тесты, эмулятор и проверки
человеком на устройстве. Debug-диагностика подробная: перед отправкой логов проверяйте
учётные данные и приватные URL. Auth-диагностика маскирует секреты и отключена в release.
Сессии аккаунта и ключи подписи не распространяются.
[Границы публикации и проверки приватности](docs/SOURCE_PUBLICATION.md).

# SloooPipe

Экспериментальная Android-интеграция **NewPipe с NewPlayer**. Цель — подключить
привычные сценарии NewPipe к NewPlayer и дать другим разработчикам реализацию,
которую можно изучить, адаптировать и использовать.

[English](README.md) · [Результаты](RESULT.md) · [Архитектура](docs/NEWPLAYER_SESSION_INTEGRATION.md)

## Состояние проекта

**Снимок исходников ZIP34 от 23 октября 2026 года.** Последняя проверенная сборка —
APK33 в LDPlayer / Android 14. Сценарий со старой мини-панелью после закрытия сессии
прошёл повторную проверку; подпись скорости соответствует движку. Найден оставшийся
недочёт вёрстки: в портретном режиме «x» переносится на вторую строку. ZIP34 меняет
только размер этой кнопки и запрещает перенос текста. Правка проверена статически;
новый APK ещё нужно собрать и проверить. Номера ZIP обозначают передачи исходников,
а не версии upstream. Стабильного релиза нет.

| Часть | Реализация и проверка |
| --- | --- |
| Сетевые ролики | Обычный Play подключён к Kotlin-координатору NewPlayer. APK33 показывает видео и сохраняет Play/Pause в 20 циклах очереди. |
| Очередь и мини-панель | Выполнены 10 циклов из плеера и 10 через мини-панель. Без выбора другого элемента текущий сохраняется; смещение позиции на паузе — до 17 мс. После отмены запуска другой страницы мини-панель показывает фактически выбранный ролик. |
| Закрытие сессии | Проверены Close из уведомления при открытом диалоге замены, устаревший OK и Back: активной сессии и старой мини-панели нет. |
| Режимы | Плавающее окно и PiP показывают видео, работают Play/Pause и возврат с сохранением позиции на паузе. Полная матрица режимов ещё не закрыта. |
| Локальные файлы | Пункт «Локальное» открывает экран системного выбора файла. Проверены mp4, пауза, перемотка, мини-панель и Close. Отмена выбора и замены сохраняет сетевую сессию. |
| Правка ZIP34 | Кнопка скорости измеряется по тексту и показывает его в одну строку. Нужна новая сборка и проверка. |
| Авторизация YouTube | Экспериментальная, отключается при сборке. Вход в аккаунт не гарантирует доступность любого ролика или сетевого адреса. |

[Доказательства APK33 и SHA256](docs/APK33_DEVICE_CHECKPOINT.md) ·
[Матрица этого прогона](docs/APK33_ACCEPTANCE.csv) ·
[Исторические широкие проверки APK32](docs/APK32_DEVICE_CHECKPOINT.md).
На последнем цикле автоматизации потребовался явный выход из полного экрана;
восстановление описано в отчёте. Результаты относятся к APK33, а не ZIP34.
По указанию пользователя слышимый звук отложен до отдельной проверки на реальном телефоне.

При выборе ещё не проигранного ролика на паузе в позиции ноль остаётся ограничение:
первый кадр может быть чёрным; после Play изображение появляется. Полная приёмка
не завершена. Нужны обе auth-сборки с тестами и полными XML/числами, остальные
источники/дорожки/история/настройки возобновления и жизненный цикл, гонки запросов,
восстановление после сетевых ошибок и физический Android 16. Старые классы плеера
и media-browser сохранены; Android Auto не проверен. Действия внешнего плеера и Kodi
остаются внешними. Полная поддержка SABR/PoToken и перенос всей интеграции на
upstream-ветку refactor в этот результат не входят.

## Сборка и тесты

Нужны Linux/WSL, JDK 21, Android SDK platform 37.0 и Build Tools 36.0.0.
Для основного приложения зафиксированы Gradle 9.8.2, AGP 9.4.1, Kotlin 2.4.21 и
Media3 1.9.2. Gradle wrapper включён. Для headless JVM-тестов shared нужны Xvfb/xauth.
SDK и зависимости должны быть установлены или доступны по сети; полного офлайн-набора здесь нет.

```bash
git clone https://github.com/andrewpozdnakov7-jpg/SloooPipe.git
cd SloooPipe/NewPipe
# Для существующей копии или архива исходников перейдите в её каталог NewPipe.
chmod +x gradlew
# Задайте JAVA_HOME и ANDROID_HOME для Linux JDK и SDK.
xvfb-run -a ./gradlew :app:testDebugUnitTest :youtube-auth-api:test :shared:jvmTest :app:verifyAuthIsolation :app:assembleDebug -Pslooopipe.withAuth=true
```

Повторите с `-Pslooopipe.withAuth=false` для варианта без авторизации. Это команды
проверки, а не заявление об успешном прохождении обоих вариантов. В исходниках 51
app/NewPlayer JVM-кейс; полные XML и количество выполненных тестов актуального цикла ещё ожидаются.
Обычная сборка checkout сохраняет APK в `NewPipe/app/build/outputs/apk/` и использует
свою debug-подпись. APK с другим сертификатом не обновит существующую установку.

Для выбора ZIP, сохранения отчётов запуска и подписи существующим внешним ключом
есть [инструкция WSL-скрипта](tools/README-wsl.md), ревизия
`20261022-09-memory-cleanup`. Скрипту нужны внешние файлы `signing/`; зависимости
сохраняются, после работы он пытается освободить чистый файловый кэш Linux в RAM.
Очистку можно отключить через `--no-memory-cleanup`. ZIP34 — текущая передача исходников; прежние архивы не менялись.
Публичная `main` содержит тот же код приложения с обновлённой документацией публикации;
в инструкции выше описано создание ZIP из копии репозитория.

## Участие и использование кода

Начните с [цели проекта](PROJECT_GOAL.md), [управления сессией](docs/NEWPLAYER_SESSION_INTEGRATION.md)
и [разбора переноса upstream](docs/UPSTREAM_PORTING_20261022.md). Общие изменения
NewPlayer отделены от NewPipe-хостов. Проверка текстового применения переносимых
патчей не заменяет сборку или принятие upstream. PR разработчикам пока не отправлялись.

В отчёте об ошибке укажите коммит, SHA256 APK, Android, вариант авторизации и шаги
воспроизведения. Разделяйте статический анализ, сборку/тесты, эмулятор и проверки
человеком на устройстве. Debug-диагностика подробная: перед отправкой логов проверяйте
учётные данные и приватные URL. Auth-диагностика маскирует секреты и отключена в release.
Сессии аккаунта и ключи подписи не распространяются.
[Границы публикации и проверки приватности](docs/SOURCE_PUBLICATION.md).
